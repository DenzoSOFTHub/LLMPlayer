## RoPE type

Dense GLM4 uses NORM RoPE in llama.cpp (`llama_model_rope_type`), because the GGUF converter does
not permute Q and K for it. Only `glm4moe` and GLM-4.xV checkpoints with multi-axis RoPE use NEOX.
LLMPlayer used NEOX for dense GLM4 until v1.18.0. The error is invisible at position 0 and grows
with position, so short prompts still looked plausible.

Measured on this model, CPU only, on the same binary with only the RoPE type changed:

| RoPE type | Teacher-forced perplexity (248 tokens of prose) |
|-----------|--------------------------------------------------|
| NEOX (before v1.18.0) | 5.45 |
| NORM (v1.18.0) | 2.60 |

## CPU Profile

Measured on the shared reference VM (8 vCPU Core Ultra 7 155H, AVX2, no GPU), so timings are
indicative only.

| Test | Result |
|------|--------|
| Retrieval prompt of 1375 tokens (employee registry, question about the first record) | Correct: "7468, Vienna" |
| Prompt processing plus 5 generated tokens | 809 s |

The packed gate+up FFN is not covered by batched prefill yet, so the prompt is processed token by
token, as for Phi-3/4.

## GPU Profile

Not measured: the reference machine has no GPU. The GPU passes read the RoPE type from the same
`ModelConfig` field, so the fix applies to them as well.
